# Звіт про виконання: Виправлення та стабілізація фази 2C (Phase 2C TDD Fixes)

**Дата:** 2026-07-07  
**Статус:** Виконано повністю, перевірено автоматичними тестами.

## Виконані роботи

Відповідно до плану виправлень для фази 2C, було реалізовано та протестовано такі покращення за методологією TDD:

1. **Реєстр специфікацій процесів (`ProcessSpec`):**
   - Додано перерахування `ProcessStatus` (`Now`, `Future`) та структуру `ProcessSpec` в `src/core/process.rs`.
   - Оголошено статичний масив `PROCESS_REGISTRY`, який містить опис вимог та статусів для всіх 7 типів `ProcessId`.
   - Створено модульний тест `tests/phase2_process_registry.rs`, який перевіряє повноту реєстру, майбутній статус поділу клітин (`Division`) та відповідність вимог capability.

2. **Інтеграція параметрів виконання у `FeasibilityResult`:**
   - Змінено варіант `FeasibilityResult::Feasible` на `Allowed { accepted_amount: f32, energy_cost: f32, resource_cost: f32 }`.
   - Оновлено перевірки `validate_feasibility` в `src/core/world.rs` та виклики в `src/core/tick.rs`.
   - Тепер обчислені на етапі валідації ліміти поглинання передаються безпосередньо у фазу виконання, запобігаючи неузгодженості конфігураційних лімітів.

3. **Прапори готовності до поділу (`RuntimeFlags::division_ready`):**
   - Додано прапор `division_ready` до структури `RuntimeFlags` у `src/core/cell_store.rs`.
   - Впроваджено логіку активації прапора при досягненні цільового радіуса клітини за умови низького тиску контакту (`max_division_pressure`).
   - Додано модульні тести в `tests/phase2_tick_phases.rs` для перевірки переходів стану прапора.

4. **Агреговані метрики діагностики процесів (`ProcessDiagnostics`):**
   - Реалізовано структуру `ProcessDiagnostics` для зведення загальної статистики спроб та відхилень запусків процесів для всього світу.
   - Додано відображення відхилених метаболічних процесів через відсутність необхідного матеріалу.

5. **Посилення перевірок парсера матеріалів:**
   - Введено поле `legacy_material_distribution` у файли TOML конфігурації.
   - Якщо прапор не встановлено, парсер конфігурації відхиляє невідомі/загальні назви матеріалів (наприклад, `unknown_goop` чи `cell_wall`), повертаючи помилку `ParseError::UnknownMaterialName`.
   - Всі старі сценарії оновлено шляхом додавання прапора зворотньої сумісності.

6. **Повне покриття херування конфігурації (`config_hash`):**
   - Розширено обчислення `config_hash()` у `src/core/config.rs` для врахування розміру світу, просторової сітки, ітерацій фізичного солвера, лімітів життєвого циклу, температурних і відхідних бар'єрів середовища, а також прапора увімкнення росту.
   - Реалізовано тести в `tests/phase2_config_hash.rs` для гарантування зміни хешу при модифікації будь-якого з цих параметрів.

7. **Документування послідовної асиметрії розподілу ресурсів:**
   - Створено документ `docs/mechanics/sequential-bias.md` (українською мовою), який описує фізику послідовної ітерації клітин у фазі поглинання та її конкурентні наслідки.
   - Зареєстровано посилання на документ у `docs/mechanics/INDEX.md`.
